## 本批函数约定

`app/m3/report_validation.py::validate_report_text(fault_type, description)` 接收两个原始值，成功返回 `(规范化类型, 规范化描述)` 二元组。参数及错误字段名仅用于模块内部，不决定未来 HTTP/数据库命名。

1. 先检查 `fault_type`，再检查 `description`；两者必须是 `str`，不调用 `str()` 强制转换。
2. 分别执行 `strip()`；结果为空字符串即拒绝。只去除首尾空白，保留内部空格、制表符、换行和中文，不折叠正文、不截断文本。
3. 失败抛出 `InvalidReportText(ValueError)`，提供 `field` 和 `reason`，错误消息也包含这两个值；`not_string` 表示类型不符，`blank` 表示去除首尾空白后为空。两项都非法时报告先检查到的字段。
4. 缺失值在本层以 `None` 表达并按 `not_string` 拒绝；两个函数参数仍为必传参数。未来 HTTP 的字段缺失如何映射由接入层确定，不在本批假造请求模型。
5. 任意非空字符串类型文本均可通过；未引入枚举及长度上限。函数不修改外部状态。
