# 任务规格

一个任务对应一个 spec：`<issue>.md`，例如 `12-seat-reservation.md`。无 GitHub Issue 时使用明确的本地编号，例如 [SPEC-000](000-repository-bootstrap.md)；创建 Issue 后补链接，不伪造任务来源。

使用 [模板](_template.md) 写清需求 ID、范围、不做项、约束、至少两个候选方案、预计修改文件、可观察验收和验证计划。引用已有 ADR，不重复其理由；新持久决策另写 proposed Note。

方案确认可以引用会话中对该范围的明确实施授权；没有授权或有新增范围时，由相应负责人确认。实现后补实际命令、结果、未运行项和人工验收状态。原方案如发生变化，更新当前规格并通过提交历史保留原因，不维护多份相互矛盾的任务正文。
