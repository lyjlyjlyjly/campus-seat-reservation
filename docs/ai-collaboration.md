# AI 协作与人工审查

执行规则统一在 [AGENTS.md](../AGENTS.md)，决策写法统一在 [Note 规范](../.agents/notes/README.md)。本文说明给组员和老师看的责任分工与证据链，不另存一份 ADR 理由。

## 谁负责什么

| 事项 | 人的职责 | AI 的职责 | 可核对证据 |
|---|---|---|---|
| 范围与验收 | 明确需求 ID、约束、负责人和验收 | 指出缺项，形成可审阅 spec | Issue / spec |
| 候选方案 | 选择方案，确认公共接口影响 | 比较至少两个方案，说明取舍 | spec；持久决策链接 Note |
| 实现与测试 | 对结果负责，理解关键代码 | 在授权范围内实现、写必要行为测试 | diff、命令与输出 |
| 公共变更 | 受影响组确认接口/字段，跨组评审 | 说明影响并维护契约与测试 | ADR、会议或 PR |
| 合并与发布 | 人工审查后提交/合并，批准生产发布 | 汇总变更及验证结果 | 提交历史、PR、发布记录 |

AI 可以辅助检查，但不能替组员作出代码已正确、需求已验收或伦理问题已解决的最终判断。提交人负责所提交结果；审阅人只能填写实际参与者。

## 一次任务的过程

1. **任务卡**：用 [.github/ISSUE_TEMPLATE/task.md](../.github/ISSUE_TEMPLATE/task.md) 指明需求、允许修改的目录、不做项、依赖和 Given–When–Then 条件。
2. **短方案**：在 [specs](specs/README.md) 比较方案，给预计文件和验证方式。涉及长期取舍时新增 proposed Note；没有新取舍时链接已有决策。
3. **确认范围**：记录人的选择；会话已经明确授权的同一工作不重复索要许可。涉及新增公共字段、权限、依赖或跨组范围时先协调，不由 AI 假定三组都已同意。
4. **小步实施**：按模块边界实现，保留原有用户改动。需要多个子代理时明确各自文件范围，主负责者检查最终集成结果；并行代理不代替跨组人工评审。
5. **验证**：AI 运行必要检查并只报告真实结果；人阅读 diff，按验收条件检查页面、权限、数据和失败路径。CI 使用 [统一脚本](../scripts/ci.py)。
6. **按模块推送与 PR**：每次 push 和每个 PR 最多涉及一个业务负责组；全局 `infra` 文件可独立推送或随该组配合，公共 D 根目录按独立范围处理。G1/M1、G2/M2＋认证/审计、G3/M3＋空间/迁移/种子及公共 D/infra 的映射见 [ADR-004](../.agents/notes/implemented/process/2026-10-23-adr-004-module-scoped-pushes.md)。跨组需求先写共享契约，再按依赖拆成独立模块 PR，不能写完几个模块后一次性推送。所有提交和 PR 标题使用带 scope 的 Conventional Commit；本地先运行 `python scripts/install_git_hooks.py` 安装门禁，GitHub PR 检查再次核对。公共层/schema 改动由另一组成员实际评审。使用 [PR 模板](../.github/pull_request_template.md) 留证；`Reviewed-by` 只有在该人真实审阅且确认署名后才填写。
7. **更新状态**：通过验收才更新需求证据并关闭任务。当前本轮验证环境是本机和 CI；未来接入服务器后再增加测试环境验证记录。

## AI 常见问题与核对方式

| 问题 | 核对动作 | 必须保留的证据 |
|---|---|---|
| 测试只断言常量、mock 掉业务 | 检查测试是否改变真实输入并观察响应/数据库；增加拒绝路径 | 测试代码和实际结果 |
| 测试无法发现规则被破坏 | 各模块后续在任务分支做一次故意破坏实验，观察失败后恢复 | 原规则、破坏点、失败及恢复后的命令/CI 链接 |
| 生成不存在的依赖/API | 检查实际版本、安装和调用结果，拒绝未经确认的新增依赖 | requirements diff、安装/测试记录 |
| 越界写表或绕过权限 | 按目录/契约审查，检查成功与无权限路径 | 受影响组评审 |
| 把计划说成完成 | 对照代码、命令和需求证据；没有实际运行就写未运行 | 需求表、spec、PR |
| 把聊天记录当工程记录 | 将授权、结论和验收压缩为可追溯的任务与决策记录 | Git/PR/Note |
| 泄漏个人数据或凭据 | 仅提供虚构/脱敏输入；检查日志、种子与提交内容 | 人工审查及真实伦理记录 |

故意破坏实验只针对已经完成且可安全恢复的业务规则，不在主分支或真实数据上操作。基础设施测试变红不能充当 M1/M2/M3 已完成该实验。
