# Agent Note: ADR-003 座位状态边界与后续 HTTP 写回

Status: proposed — 跨模块链路本轮延期，等待契约和课程验收口径确认

Date: 2026-10-20
Owner: G1、G3；涉及整教室占用时加入 G2
References: [需求基线](../../../../docs/requirements.md)、[PJ 计划书](../../../../docs/PJ-计划书.md)

## Problem

D 管理座位是否存在、位置和插座等主数据；M1 管预约时段与可预约状态。后续维修和整教室占用会影响 M1，直接从其他模块改表会模糊权限、追溯和恢复责任。课程还要求至少一次真正的跨模块网络调用。

## Proposal

优先讨论 M3→M1 链路：工单进入 IN_REPAIR 时以 HTTP 请求阻塞座位，验收 DONE 后释放。请求以来源和工单引用号支持重复调用，状态记录保留来源。接口路径草案来自计划：`POST /internal/seat-blocks`、`DELETE /internal/seat-blocks/M3/{refId}`；这些路径尚未实现或冻结。

同一 FastAPI 进程通过 localhost HTTP 实现网络边界的方式，需确认老师接受。内部调用令牌、请求字段、超时、失败重试以及数据库事务边界先在 spec 定义。本轮没有这条链路，也不增加假接口。

## Alternatives considered

| 方案 | 收益 | 代价 / 取舍 |
|---|---|---|
| 单体中的 localhost HTTP | 满足真实网络行为的候选方式，保留一个部署单元 | 需课程确认及超时、锁竞争、失败一致性设计；作为后续提案 |
| 直接调用 Python 函数 | 实现和本地测试简单 | 不能作为课程要求的网络调用演示 |
| M3 直接改 M1 表 | 短期代码少 | 打破数据所有权，绕过 M1 状态校验和追溯 |
| 提前拆分服务 | 网络和进程边界明确 | 增加部署、配置和一致性处理成本 |

AI 初始建议：按长期计划优先验证 M3→M1；当前建议与两天范围一致，先保留提案。组内最终选择和教师确认均未记录。

## Acceptance criteria

- Given 三组冻结状态边界，When 评审接口契约，Then 明确 D 与 M1 的数据所有权及失败处理，不通过共享表绕过接口。
- Given 真实 Uvicorn 进程，When 经 HTTP 发起维修和验收链路，Then M1 状态随之变化，重复调用不产生重复阻塞，记录可追溯来源。
- Given HTTP 失败或 SQLite 锁冲突，When 状态推进失败，Then 不返回虚假成功，按契约保留可重试的一致状态。
- Given 课程接受部署形态，When 采纳 Note，Then 附真实确认记录。

## Risks

调用前持有 SQLite 写事务可能导致回调等待锁；不得在未设计事务边界时直接实现“更新工单后同步 HTTP”。不在本轮添加 outbox 或补偿框架。M2 占用/恢复及冲突预约处理另行讨论，不能用本 Note 直接批准该范围。
